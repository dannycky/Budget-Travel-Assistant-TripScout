# TripScout — AI Assistant for Budget Travellers

A travel chatbot that combines **live flight & hotel search** (SerpApi) with a
**RAG knowledge base** of budget travel guides built from
[Wikivoyage](https://en.wikivoyage.org), covering 60+ cities (major Asia-Pacific
destinations + European cities).

## Features

- ✈️ **Live flight search** — real prices via SerpApi's Google Flights API, with
  a direct Google Flights booking link in every answer
- 🏨 **Live hotel search** — real prices/ratings via SerpApi's Google Hotels API,
  with per-hotel booking links
- 📚 **Travel guide RAG** — budget-focused city guides (sightseeing by category,
  budget eats, hostels, cheap drinks, commute tips) retrieved on demand via BM25
- 🧠 **Smart tool routing** — the LLM picks the right tool per question; date
  comparisons (e.g. "which week is cheapest?") are capped at 6 windows
- 💬 **ChatGPT-style UI** — daisyUI + Tailwind, markdown formatting, clickable
  booking links, loading animations

## Setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Create a `.env` in the project root:

```
# Required — chat LLM (from https://openrouter.ai/keys)
OPENROUTER_API_KEY=...

# Required — live flight & hotel search (from https://serpapi.com)
SERPAPI_API_KEY=...

# Optional — any OpenRouter model that supports tool/function calling
# (defaults to deepseek/deepseek-v3.2 if unset)
MODEL_NAME=deepseek/deepseek-v3.2

# Optional — custom OpenAI-compatible API base for the chat LLM
# (defaults to https://openrouter.ai/api/v1 if unset)
OPENAI_API_BASE=https://openrouter.ai/api/v1
```

## Run

```bash
python app.py
# open http://127.0.0.1:5001
```

(Port 5001 — macOS AirPlay Receiver occupies 5000 by default.)

## Refreshing the travel guides

The `md/` folder holds the knowledge base, generated by `build_guides.py`
from Wikivoyage (free, public, no API key needed). To refresh with updated
content:

```bash
# Fill in missing cities only (safe to re-run; also resumes after failures)
python build_guides.py

# Force-refresh ALL cities (~15 min; if a few fail due to rate limits,
# just run the same command again — it only fetches what's missing)
python build_guides.py --all

# Refresh specific cities
python build_guides.py --city tokyo osaka

# Offline / no rate limits: parse a local XML dump instead of the API
# (download from https://dumps.wikimedia.org/other/wikivoyage/)
python build_guides.py --dump enwikivoyage-latest-pages-articles.xml.bz2
```

**After refreshing, restart the server** (`python app.py`) — the BM25
retrieval index is rebuilt from `md/` at startup.

## Project structure

```
app.py            Flask server: GET / (UI), POST /chat (API)
chatbot.py        LangGraph agent: 3 tools + tool routing rules
build_guides.py  Wikivoyage -> md/ pipeline (re-runnable)
templates/       Chat frontend (daisyUI + Tailwind via CDN)
md/              Generated city guides (62 cities)
```

## How it works

1. User asks a question in the chat UI
2. The LLM (via OpenRouter) routes to the right tool:
   - Flights → `search_google_flights` (SerpApi)
   - Hotels → `search_hotels` (SerpApi)
   - Activities/food/transport → `search_travel_guides` (local BM25)
   - Unsure → defaults to the travel guides tool
3. Tools return compact, parsed results (top 3 + booking links)
4. The LLM composes a grounded answer with markdown + links
